Browser-only edition

Tapziq browser privacy

Last updated: August 15, 2026

Open app Overview Privacy Third-party notices

Short version

Tapziq's browser application code does not send editor text, selections, or Gemma suggestions to a Tapziq server or another inference service. Proofreading runs locally in a dedicated browser worker with the downloaded Gemma 4 E2B-it model and WebGPU.

The on-page virtual keyboard works only in Tapziq's own editor. It is not an Android system keyboard and cannot access text in other apps, sites, fields, or tabs. The native Android keyboard has a different platform boundary and is not covered by this document.

The app and model still require ordinary network requests for initial setup and updates. Those requests reveal normal connection metadata to their hosts, but Tapziq does not put editor text in them.

Text and proofreading

  • Text entered or pasted into the editor remains in volatile page and dedicated-worker memory.
  • Only after Proofread does Tapziq pass the selected passage—or an eligible whole editor—to the local worker. The limit is 500 UTF-16 code units.
  • The result remains in memory and appears as a preview. Only Apply changes the editor. Dismiss and Cancel do not.
  • Tapziq rejects the result if the original text or selection has changed.
  • Tapziq application code does not persist editor contents, selections, prompts, model responses, typing history, or clipboard contents.
  • Native browser spellcheck, autocomplete, and autocapitalize are disabled on the editor. Tapziq does not request clipboard permission.

Closing or reloading the page discards editor state maintained by Tapziq's code. A browser or operating system may independently retain process memory, session restoration data, swap, crash reports, or other artifacts outside Tapziq's application-level controls.

Model and app storage

After explicit confirmation, Tapziq stores these items for the PWA's browser origin:

  • gemma-4-E2B-it-web.litertlm, including a partial paused download, in OPFS;
  • verification metadata containing the filename, pinned revision, byte count, SHA-256, LiteRT-LM version, modification time, and verification time; and
  • the app shell, worker, self-hosted LiteRT-LM WebAssembly/runtime, manifest, styles, and icon in the service-worker cache.

Tapziq asks the browser for persistent storage before downloading. A grant is not guaranteed. The browser may evict non-persistent data, and the user can clear site data at any time.

This is browser-managed, origin-scoped storage. It is separate from native Android private files and does not use Gemini Nano, Android AICore, or ML Kit. Other websites ordinarily cannot read another origin's OPFS or cache. That boundary does not prevent access by the browser, operating system, sufficiently privileged extensions or administrators, developer tools, malware, or anyone controlling the browser profile or device.

Network activity

  1. Tapziq app origin: loads or updates HTML, JavaScript, CSS, icon, manifest, service worker, and self-hosted LiteRT-LM WebAssembly/runtime.
  2. Hugging Face model hosting: after download confirmation, retrieves or resumes the exact pinned model. The request omits credentials, bypasses HTTP cache, and sends no referrer.

These hosts can receive normal HTTP and transport metadata such as IP address, time, path, response size, and browser or network headers. Hosting providers may retain access or security logs under their policies. Tapziq source does not add editor text, suggestions, or prompts to any request URL, header, or body.

Once the current shell, runtime, and verified model are present, inference needs no network request. Tapziq contains no account system, advertising SDK, analytics SDK, telemetry endpoint, or remote inference client, and its application code does not write cookies.

Removal and user controls

  • Remove browser model deletes the complete or partial model and verification metadata from OPFS.
  • The browser's site-data controls remove the model, app cache, service worker, and other origin data together.
  • Uninstalling the PWA does not clear site data in every browser. Use the site-data control when deletion matters.
  • Closing the page clears Tapziq's in-memory editor and suggestion, subject to the browser and operating-system caveats above.

These controls are commonly named Site settings, Storage, Clear data, or Delete site data.

Scope and changes

This statement covers the source behavior of the browser edition. A deployment operator can still observe normal requests to its host, while browser extensions and modified builds can change the boundary. Review the deployed origin and browser permissions when that distinction matters.
